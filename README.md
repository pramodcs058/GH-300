# 🚀 GH-300 — GitHub Copilot Training Repository

Welcome to the **GH-300: GitHub Copilot** training repository.

This repository is designed for **GitHub Copilot training participants** to access hands-on labs, challenges, reference material, useful links, and certification preparation resources.

The goal of this repository is to help you move from **understanding GitHub Copilot concepts** to **using Copilot effectively in real-world software development workflows**.

---

## 🎯 Learning Objectives

By working through the resources in this repository, you will learn how to:

- Understand GitHub Copilot and its capabilities.
- Use Copilot for code completion and code generation.
- Use Copilot Chat effectively in Visual Studio Code.
- Work with different Copilot interaction modes.
- Provide effective prompts and context to Copilot.
- Analyze and understand an existing codebase.
- Generate, modify, refactor, and debug code using Copilot.
- Develop and improve automated tests using Copilot.
- Use Copilot across the software development lifecycle.
- Explore advanced capabilities such as **Agent Mode, Plan Mode, MCP, and Copilot Spaces**.
- Apply responsible AI and secure development practices when working with AI-assisted coding tools.

## 🧪 Hands-on Labs

The [`labs`](./labs) folder contains practical exercises that can be completed during the GH-300 training.

The labs are designed to provide hands-on experience with GitHub Copilot using real development scenarios.

### Recommended Lab Approach

For each lab:

1. Read the objective carefully.
2. Complete the setup and prerequisites.
3. Open the application/project in Visual Studio Code.
4. Use the specified GitHub Copilot feature or interaction mode.
5. Review Copilot's response before accepting any changes.
6. Test the generated or modified code.
7. Verify that the requested functionality works correctly.
8. Continue to the next exercise.

> **Important:** GitHub Copilot is an AI assistant. Always review, understand, test, and validate the code generated by Copilot before using it.

# 💡 Tips for Using GitHub Copilot

### 1. Give Copilot Context

Instead of asking:

```text
Fix this code.
```

Provide meaningful context:

```text
#codebase
Users are able to register twice for the same activity.
Find the likely source of the problem and explain the root cause.
```

### 2. Start with Understanding

Before asking Copilot to modify code, ask it to explain:

- Project structure
- Existing implementation
- Dependencies
- Data flow
- Relevant functions/classes

### 3. Review Before Accepting

Do not blindly accept generated code.

Check:

- Correctness
- Security
- Performance
- Maintainability
- Compatibility with the existing application

### 4. Test Everything

After modifying code:

```text
Run
→ Test
→ Observe
→ Debug
→ Refine
```

### 5. Use Iterative Prompting

A good Copilot interaction is usually conversational.

```text
Understand
   ↓
Plan
   ↓
Implement
   ↓
Test
   ↓
Improve
```

# ⚠️ Important Reminder

GitHub Copilot can generate useful code, but generated code may contain:

- Incorrect assumptions
- Bugs
- Security issues
- Inefficient implementations
- Outdated approaches
- Unnecessary code

**You are responsible for reviewing and validating AI-generated output.**

Always understand what Copilot generates before committing or deploying it.
